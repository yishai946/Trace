# TRACE: החלטות טכנולוגיה

המסמך מתעד את ה-stack שנבחר ואת הסיבות. שינוי באחת ההחלטות מתעדכן כאן, עם הסיבה.

## מבנה

- **Monorepo אחד עם pnpm workspaces.** שלוש אפליקציות ב-`apps/*` וקוד משותף ב-`packages/*`. כל אפליקציה נבנית ונפרסת בנפרד.
- **שרת אחד, מונולית מודולרי.** כל תחום הוא מודול בתוך `apps/api` (missions, polygons, searchers, reports, sos, tracking, notifications). אין מיקרו-סרוויסים: צוות קטן, MVP, ופעולות כמו SOS, שיבוץ ו-Coverage צריכות עקביות של בסיס נתונים אחד.

| חבילה            | תפקיד                                                                          |
| ---------------- | ------------------------------------------------------------------------------ |
| `@trace/api`     | השרת: REST, WebSocket, עבודות רקע                                              |
| `@trace/command` | מערכת ה-Web של מנהל המסע                                                       |
| `@trace/field`   | אפליקציית המחפש (React Native)                                                 |
| `@trace/schemas` | סכמות zod לבקשות ותשובות, משותפות לשרת ולשתי האפליקציות                        |
| `@trace/domain`  | לוגיקה עסקית טהורה, בלי framework ובלי בסיס נתונים                             |
| `@trace/design`  | מערכת העיצוב Trace Console: tokens ל-Web ול-React Native, מסונכרנת מה-artifact |
| `@trace/geo`     | גיאומטריה ו-ITM: המרות, בתוך/מחוץ לפוליגון, מרחק מגבול, שטח                    |
| `@trace/map`     | סגנון המפה ושכבות המסע, נבנים מה-tokens; משותף ל-Web ול-React Native           |

## מפה

| תחום         | בחירה                                                             | למה                                                                                                     |
| ------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| נתוני מפה    | MapTiler: אריחים וקטוריים בסכמת OpenMapTiles, terrain-rgb, גופנים | התחלה מהירה עם מפתח אחד. הסגנון תלוי רק ב-URLs (`MapProvider`), כך שמעבר לאריחים מאוחסנים לא משנה סגנון |
| סגנון        | סגנון משלנו (`buildMapStyle`) שנבנה מה-tokens של שתי הערכות       | המפה חלק ממערכת העיצוב; בדיקה אוכפת שכל צבע בשכבות הוא token                                            |
| תבליט        | hillshade ותלת-ממד מ-DEM; קווי גובה מ-maplibre-contour            | קווי גובה נוצרים בדפדפן מאותו DEM, בלי תלות בספק                                                        |
| ציור         | terra-draw                                                        | ציור פוליגונים עם בדיקת חיתוך עצמי                                                                      |
| חיפוש מקומות | MapTiler Geocoding בעברית, מוגבל לגבולות ישראל                    | מסנן המדינה של MapTiler לא מחזיר תוצאות לישראל; תיבת גבולות כן                                          |
| עברית ו-RTL  | מובנה ב-MapLibre 6                                                | אין צורך בתוסף RTL                                                                                      |
| מפתח         | `MAPTILER_API_KEY` ב-`apps/command/.env.local`                    | מפתח לקוח ציבורי; יש להגביל אותו לדומיינים בהגדרות MapTiler                                             |

## החלטות פתוחות

- ספק SMS לישראל.
- מעבר מ-MapTiler לאריחים מאוחסנים (PMTiles בסכמת OpenMapTiles ו-DEM), כולל רישיון לשמירה Offline ב-Field.
- פלטת צבעים ייעודית למפת הבסיס במערכת העיצוב (כרגע נגזרת מ-tokens ניטרליים בשקיפות).
- תמיכה בתלת-ממד ב-MapLibre Native.
- תשתית ואחסון: בהחלטת איש התשתיות. הדרישה היחידה מהקוד: PostgreSQL עם PostGIS.
- פרמטרים שמסומנים TBD באפיון (סף סוללה, זמני הסלמה, אלגוריתם Coverage).
