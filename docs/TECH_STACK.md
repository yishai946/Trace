# TRACE: החלטות טכנולוגיה

המסמך מתעד את ה-stack שנבחר ואת הסיבות. שינוי באחת ההחלטות מתעדכן כאן, עם הסיבה.

## מבנה

- **Monorepo אחד עם pnpm workspaces.** שלוש אפליקציות ב-`apps/*` וקוד משותף ב-`packages/*`. כל אפליקציה נבנית ונפרסת בנפרד.
- **שרת אחד, מונולית מודולרי.** כל תחום הוא מודול בתוך `apps/api` (missions, polygons, searchers, reports, sos, tracking, notifications). אין מיקרו-סרוויסים: צוות קטן, MVP, ופעולות כמו SOS, שיבוץ ו-Coverage צריכות עקביות של בסיס נתונים אחד.

| חבילה            | תפקיד                                                                          |
| ---------------- | ------------------------------------------------------------------------------ |
| `@trace/api`     | השרת: REST, WebSocket, עבודות רקע                                              |
| `@trace/command` | מערכת ה-Web של מנהל המסע                                                       |
| `@trace/field`   | אפליקציית המחפש (React Native)                                                 |
| `@trace/schemas` | סכמות zod לבקשות ותשובות, משותפות לשרת ולשתי האפליקציות                        |
| `@trace/domain`  | לוגיקה עסקית טהורה, בלי framework ובלי בסיס נתונים                             |
| `@trace/design`  | מערכת העיצוב Trace Console: tokens ל-Web ול-React Native, מסונכרנת מה-artifact |
| `@trace/geo`     | גיאומטריה ו-ITM: המרות, בתוך/מחוץ לפוליגון, מרחק מגבול, שטח                    |
| `@trace/map`     | סגנון המפה ושכבות המסע, נבנים מה-tokens; משותף ל-Web ול-React Native           |

ה-outbox נמצא ב-`apps/field/src/outbox` (טבלה אחת, `trace-outbox.db`). נקודות GPS ותצפיות (UC-F10) עוברות דרכו: `receiveFixes` שומר כל קליטה בו, ושולח כשיש קליטה, בחזרת החיבור ובחזרת האפליקציה לחזית. פריט נמחק רק אחרי אישור 2xx של השרת. סירוב סופי של השרת (409/404/403 על המשימה, 400 על האצווה) מוחק את הפריטים; שגיאת רשת או שרת משאירה אותם. תצפית נשמרת בו עם מזהה UUIDv7 שנוצר בטלפון, והשרת עונה 200 על מזהה שכבר שמר, כך ששליחה חוזרת אינה יוצרת כפילות. `SIGHTING_ID_TAKEN` או 400 מוחקים את התצפית; 409/404/403 מוחקים את תצפיות המסע. ה-outbox מתרוקן ביציאה מהחשבון. Drizzle נדחה עד שיהיו כמה טבלאות מקומיות.

## אימות והרשאות

- כל נתיב תחת `/api` דורש משתמש מחובר, חוץ מ-`/api/health` ומנתיבי Better Auth תחת `/api/auth`. בלי session מוחזר 401 `UNAUTHENTICATED`.
- **מנהל** נכנס באימייל וסיסמה (`/api/auth/sign-in/email`) ו-Command שולח את עוגיית ה-session. אין הרשמה עצמית: חשבון מנהל נוצר בפקודה `pnpm --filter @trace/api auth:create-commander --email <אימייל> --name <שם> --password <סיסמה>`. ה-seed יוצר מנהל פיתוח (`commander@trace.local`, הסיסמה ב-`apps/api/src/scripts/seed.ts`).
- **מחפש** נכנס בטלפון ו-OTP (`/api/auth/phone-number/send-otp`, ואז `/verify`); הכניסה הראשונה יוצרת משתמש בתפקיד `searcher`. Field שולח את ה-token שמוחזר כ-`Authorization: Bearer <token>`. פרופיל המחפש נוצר כשהוא מזין שם (`PUT /api/searchers/me`); עד אז `GET /api/searchers/me` מחזיר 404 ו-Field מציג את מסך השם (UC-F01). מספר בקשות הקוד לכל מספר טלפון מוגבל (`OTP_REQUEST_LIMIT` ב-`apps/api/src/auth`), ומעבר לו מוחזר 429 עם `Retry-After`. תוקף הקוד ומספר הניסיונות הם ברירות המחדל של Better Auth עד להחלטה. עד שייבחר ספק SMS הקוד נכתב ללוג של השרת, ובפרודקשן שליחה נכשלת. Field שומר את ה-token במכשיר ב-`expo-secure-store` (`AFTER_FIRST_UNLOCK`, כדי שמשימות ברקע יוכלו לקרוא אותו), ופותח את האפליקציה לפיו: בלי token מסך הכניסה, עם token ובלי פרופיל מסך השם, ואחרת ממשיך גם בלי חיבור. בקשות Field לא שולחות עוגיות (`credentials: 'omit'`).
- מטריצת ההרשאות (אפיון §7) נאכפת ב-`apps/api/src/auth/auth.access.ts`: מסע שאינו של המשתמש מחזיר 404; מחפש במסע שמבקש פעולת מנהל מקבל 403 `FORBIDDEN`. מחפש רואה את המסעות שהוא משתתף בהם ואת המפה שלהם, אבל לא את מיקומי המחפשים האחרים. מחפש במסע (גם במצב Available, אם הפעילות שלו לא הסתיימה) רשאי לשלוח תצפית (`POST /missions/:id/sightings`, UC-F10), אבל רק המנהל רואה את רשימת התצפיות ומחליט על LKP. רק מחפש במסע שפעילותו לא הסתיימה מפעיל SOS (`POST /missions/:id/sos`, UC-F13), בכל מצב מסע; המחפש ששלח או המנהל סוגרים אותו, ומחפש אחר במסע מקבל 403.
- בפרודקשן חובה להגדיר `AUTH_SECRET` (לפחות 32 תווים) ו-`API_URL`.

## זמן אמת

- Socket.IO על אותו שרת, בנתיב `/api/realtime` (`apps/api/src/realtime`). שמות האירועים והמבנה שלהם ב-`@trace/schemas` (`realtime.ts`).
- החיבור מאומת באותו session כמו ה-REST: Command שולח את העוגייה, Field שולח את ה-token ב-`auth: { token }`. בלי session החיבור נדחה (`UNAUTHENTICATED`), החיבור בודק את ה-session מחדש כל 30 שניות ונסגר כשה-session פג או בוטל (יציאה במקום אחר).
- הלקוח מצטרף לכל מסע שהוא מציג (`mission:join`) לפי אותם כללים כמו ה-REST: מסע זר מחזיר `NOT_FOUND`. אירועים מגיעים רק למי שהצטרף, בערוץ `mission:event`.
- מיקומי מחפשים (`participant.moved`) ונקודות חדשות במסלול (`participant.tracked`, רק הנקודות שהעלאה שמרה עכשיו) מגיעים רק למנהל המסע, גם לא למחפש עצמו (החלטה 32). המסלול המלא נקרא מ-`GET /api/missions/:id/participants/:participantId/track`, למנהל המסע בלבד, גם אחרי סיום המשתתף או המסע. סוללה (`PUT /api/missions/:id/participation/battery`): הקריאה העדכנית ביותר לפי `measuredAt` גוברת, ושינוי נשלח כ-`participant.updated`. שינויי פוליגונים מגיעים לכל חברי המסע. תצפיות (`sighting.saved`) מגיעות רק למנהל המסע. שינוי LKP (`lkp.changed`) מגיע לכל חברי המסע מיד, ומי שהיה מנותק מקבל אותו בטעינה מחדש אחרי החיבור (החלטה 87).
- SOS (`sos.saved`, הפעלה וסגירה) מגיע למנהל, לשולח ולמחפשים ששובצו לפוליגון של השולח ברגע ההפעלה. הרשימה נשמרת ואינה מחושבת מחדש, והסגירה נשלחת לאותם אנשים (החלטות 98 ו-99). מי שהיה מנותק קורא את `GET /api/missions/:id/sos` אחרי החיבור.
- אירועי ציר הזמן (`timeline.recorded`, UC-C19) מגיעים רק למנהל המסע. רישום אירוע נעשה בתוך הטרנזקציה של השינוי (`recordEvent` ב-`apps/api/src/modules/timeline`), והפרסום אחרי שהיא נשמרת.
- שינוי פרטי מסע ונעדר או תמונת הנעדר (`mission.updated`, עם המסע כולו) מגיע לכל חברי המסע (UC-C03). מחפש מנותק מקבל אותם מ-`GET /api/missions/:id` אחרי שחזר.
- אירועים שנשלחו בזמן ניתוק לא נשלחים שוב: אחרי התחברות מחדש הלקוח מצטרף שוב וטוען מחדש את נתוני המסע. ב-Command נורית החיבור מראה "לא זמין" כל עוד המפה לא מתעדכנת, ופעולות חדשות חסומות.

## Push

שליחה דרך Expo Push (`expo-server-sdk`), מאחורי ממשק `PushSender` (`apps/api/src/modules/notifications`). בבדיקות מחליפים אותו בזיוף.

- Field שולח `PUT /api/push-token` אחרי התחברות ובכל פעם ש-Expo נותן token חדש, ו-`DELETE /api/push-token` כשההרשאה בוטלה. ה-token שייך ל-session: יציאה מהמערכת מוחקת אותו גם כשהמכשיר מנותק. מכשיר משותף: אותו token שנרשם על ידי מחפש אחר עובר אליו.
- `createPushNotifier(...).notifySearchers({ missionId, polygonId?, excludeSearcherIds?, message })` שולח רק למחפשים פעילים במסע (לא "סיום פעילות", בכל סטטוס מסע) עם session בתוקף. עם `polygonId`: רק למשובצים לפוליגון (החלטות 98 ו-100). הכשל בשליחה נרשם ביומן ואינו נזרק; Realtime נשאר ערוץ ההתראה בתוך האפליקציה.
- token ש-Expo מחזיר עבורו `DeviceNotRegistered` נמחק בעת השליחה. קבלות (receipts) עדיין לא נבדקות.
- `EXPO_ACCESS_TOKEN` אופציונלי (Expo "enhanced push security"); לא נשמר בקוד.
- אירועי השליחה עצמם (SOS, שיבוץ, הודעות) יתחברו אל `notifySearchers` בתוך הנושאים שלהם.

מגבלות שנמצאו (מתועדות, לא הוחלט עליהן; הפריט TBD באפיון נשאר פתוח):

- Android: Expo Go לא תומך ב-Push מ-SDK 53, נדרש development build. מ-Android 13 חלון ההרשאה לא מופיע לפני שנוצר ערוץ התראות.
- iOS: Push דורש entitlement של `aps-environment`, שאינו זמין בחתימה חינמית (Sideloadly, #115).
- token אמיתי דורש פרויקט EAS (`extra.eas.projectId`) ואישורי FCM (Android) ו-APNs (iOS) שהועלו ל-EAS.
- `DeviceNotRegistered` עלול להגיע רק בקבלה כ-15 דקות אחרי השליחה; בדיקת קבלות דורשת job ברקע (pg-boss).
- אפליקציה שנסגרה: התראה עם תוכן גלוי מוצגת על ידי מערכת ההפעלה; התראה שקטה (data-only) אינה מובטחת, ובפרט ב-iOS אחרי סגירה יזומה.

## פיתוח מקומי

בסיס הנתונים המקומי רץ ב-Docker (`docker-compose.yml`, ‏PostGIS על פורט 5433, כדי לא להתנגש ב-PostgreSQL שמותקן על המחשב). הפריסה לסביבות אחרות בהחלטת איש התשתיות.

| פקודה             | מה היא עושה                                         |
| ----------------- | --------------------------------------------------- |
| `pnpm db:up`      | מפעיל את בסיס הנתונים                               |
| `pnpm db:migrate` | מריץ migrations שעוד לא רצו                         |
| `pnpm db:seed`    | יוצר מסע לדוגמה ומנהל פיתוח (רק כשבסיס הנתונים ריק) |
| `pnpm db:reset`   | מוחק את כל הנתונים המקומיים ומריץ migrations מחדש   |

שינוי בסכמה (`apps/api/src/db/schema.ts`) מלווה תמיד ב-migration: `pnpm --filter @trace/api db:generate`.

בדיקות השרת רצות מול בסיס נתונים אמיתי (`trace_test`, שנוצר מחדש בכל הרצה), ולכן `pnpm test` דורש `pnpm db:up`.

## החלטות פתוחות

- ספק SMS לישראל.
- פרויקט EAS ואישורי Push (FCM ו-APNs), ובדיקת קבלות Expo.
- מעבר מ-MapTiler לאריחים מאוחסנים (PMTiles בסכמת OpenMapTiles ו-DEM), כולל רישיון לשמירה Offline ב-Field.
- פלטת צבעים ייעודית למפת הבסיס במערכת העיצוב (כרגע נגזרת מ-tokens ניטרליים בשקיפות).
- תמיכה בתלת-ממד ב-MapLibre Native.
- תשתית ואחסון: בהחלטת איש התשתיות. הדרישה היחידה מהקוד: PostgreSQL עם PostGIS.
- פרמטרים שמסומנים TBD באפיון (סף סוללה, זמני הסלמה, אלגוריתם Coverage).
